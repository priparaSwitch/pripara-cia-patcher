# SHA-256 검사 제거 버전 (2026.10.02.1)

최신 업로드 소스를 기준으로 SHA-256 비교에 따른 패치 거부를 제거했습니다.

- Xdelta 파일의 SHA-256, 원본 RomFS의 SHA-256, 결과 ExeFS/RomFS의 SHA-256을 검사하지 않습니다.
- 아이콘 헤더 및 정규화 결과의 SHA-256 일치 여부를 검사하지 않습니다.
- ExeFS SHA-256 계산은 알려진 아이콘 변형에 맞는 패치 경로를 선택하는 용도로만 유지합니다. 등록되지 않은 해시는 공통 exefs.bin.xdelta를 선택합니다.
- CIA Title ID, 복호화 여부, 구조, 크기, 패치 파일 다운로드/빈 파일 검사는 유지합니다.
- Xdelta 자체의 델타 체크섬은 유지합니다. 잘못된 원본/패치 조합은 Xdelta 엔진에서 실패할 수 있습니다.
- 설치에 필요한 ExeFS, NCCH, TMD의 SHA-256 재계산은 유지합니다.

## 패치 교체

`public/patches/exefs.bin.xdelta`와 `public/patches/romfs.xdelta`를 교체하면 됩니다.
패치 파일 해시와 패치 결과 해시는 config.js에 입력할 필요가 없습니다.

`exefs_variant.xdelta`는 알려진 아이콘 변형의 레거시 경로에서만 사용합니다.
첨부 원본에서 이 파일은 이전 버전이므로, 새 공통 패치와 같은 결과로 맞추려면
별도로 새로 만들어 교체해야 합니다. 기본 패치하기는 정규화 후 공통 패치를 사용합니다.

## 빌드 및 배포

```sh
npm ci
npm run build
```

기존 GitHub Pages 워크플로를 그대로 사용합니다. 배포 버전은 config.js의 siteVersion입니다.
CIA는 브라우저에서 처리하며 서버에 전송하지 않습니다.

## 확인 범위

수정 모듈의 구문 검사와 패치 다운로드, 공통/아이콘 변형 경로, 해시 설정 없이 실행,
아이콘 정규화 및 헤더 해시 재계산을 테스트했습니다.
실제 CIA 생성 및 실기 설치/실행은 원본 CIA가 없어 확인하지 못했습니다.
